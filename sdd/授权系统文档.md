# 族谱软件授权系统文档

## 概述

族谱软件授权系统采用客户端-服务器架构，支持年度授权和永久授权两种模式。

## 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                    授权服务器（Python/FastAPI）               │
│  地址: http://YOUR_SERVER_IP:80                             │
└─────────────────────────────────────────────────────────────┘
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
┌─────────────────────────┐   ┌─────────────────────────────┐
│   族谱桌面端 (Rust)      │   │   客户端上报 (Rust)          │
│   - 激活授权             │   │   - 使用情况统计              │
│   - 验证授权             │   │   - 每日中午12点上报         │
└─────────────────────────┘   └─────────────────────────────┘
```

## 数据库表设计

### license_keys（授权码表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| license_key | TEXT | 授权码，唯一 |
| license_type | TEXT | 类型：year（年度）/ permanent（永久） |
| machine_code | TEXT | 绑定的机器码 |
| activated_at | TEXT | 激活时间 |
| expires_at | TEXT | 过期时间（永久版为NULL） |
| revoked | INTEGER | 是否被撤销（0/1） |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

### usage_logs（操作日志表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| machine_code | TEXT | 机器码 |
| action | TEXT | 操作类型：activate / verify / reject |
| license_key | TEXT | 关联的授权码 |
| ip_address | TEXT | 客户端IP |
| created_at | TEXT | 时间 |

### usage_reports（使用情况上报表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| app_version | TEXT | 应用版本 |
| os_name | TEXT | 操作系统名称 |
| os_version | TEXT | 操作系统版本 |
| public_ip | TEXT | 公网IP |
| country | TEXT | 国家 |
| region | TEXT | 省份/地区 |
| city | TEXT | 城市 |
| report_date | TEXT | 上报日期 |
| created_at | TEXT | 创建时间 |

## API 接口

### 1. 激活授权

**请求**
```
POST /api/license/activate?machine_code={机器码}
Content-Type: application/json

{
  "license_key": "GLY-XXXX-XXXX-XXXX-XXXX"
}
```

**响应（成功）**
```json
{
  "success": true,
  "data": {
    "license_type": "year",
    "activated_at": "2026-04-28 12:00:00",
    "expires_at": "2027-04-28 12:00:00"
  }
}
```

**响应（失败）**
```json
{
  "detail": "授权码无效"
}
```

### 2. 验证授权

**请求**
```
POST /api/license/verify?machine_code={机器码}
Content-Type: application/json

{
  "license_key": "GLY-XXXX-XXXX-XXXX-XXXX"
}
```

**响应（成功）**
```json
{
  "success": true,
  "data": {
    "valid": true,
    "license_type": "year",
    "expires_at": "2027-04-28 12:00:00"
  }
}
```

**响应（失败）**
```json
{
  "detail": "授权已过期"
}
```

### 3. 使用情况上报

**请求**
```
POST /api/license/report
Content-Type: application/json

{
  "reports": [
    {
      "app_version": "0.1.1",
      "os_name": "macOS",
      "os_version": "15.0",
      "public_ip": "1.2.3.4",
      "country": "中国",
      "region": "广东",
      "city": "深圳",
      "report_date": "2026-04-28"
    }
  ]
}
```

**响应**
```json
{
  "success": true,
  "count": 1
}
```

### 4. 使用统计（管理员）

**请求**
```
GET /api/license/stats
```

**响应**
```json
{
  "success": true,
  "data": {
    "total_reports": 100,
    "reports_by_date": [{"date": "2026-04-28", "count": 5}],
    "reports_by_country": [{"country": "中国", "count": 80}],
    "recent_reports": [...]
  }
}
```

## 服务器部署

### 启动服务器

```bash
cd license-server
pip install -r requirements.txt
python main.py
```

### 生成授权码（手动）

授权码需要管理员手动插入数据库：

```bash
sqlite3 license_server.db
```

```sql
-- 插入年度授权码
INSERT INTO license_keys (license_key, license_type) VALUES ('GLY-AAAA-BBBB-CCCC-DDDD', 'year');

-- 插入永久授权码
INSERT INTO license_keys (license_key, license_type) VALUES ('GLP-1111-2222-3333-4444', 'permanent');
```

### 生成授权码脚本

也可以通过 API 创建授权码：

```bash
curl -X POST http://YOUR_SERVER_IP:80/api/license/create_key \
  -H "Content-Type: application/json" \
  -d '{"license_key": "GLY-XXXX-YYYY-ZZZZ-WWWW", "license_type": "year"}'
```

## 授权码格式

- **年度授权**：`GLY-XXXX-XXXX-XXXX-XXXX`（GLY开头）
- **永久授权**：`GLP-XXXX-XXXX-XXXX-XXXX`（GLP开头）

实际使用中，授权码由管理员生成并提供给用户，格式可自定义，只需确保在数据库中唯一即可。

## 客户端行为

### 首次激活流程

1. 用户打开"设置" -> "授权管理"
2. 输入授权码
3. 客户端自动生成机器码（基于硬件信息）
4. 客户端将 机器码 + 授权码 发送到服务器
5. 服务器绑定机器码和授权码
6. 返回激活成功/失败

### 验证流程

1. 客户端每日中午12点自动验证
2. 也可手动点击"验证授权"按钮
3. 验证通过则继续使用，失败则提示

### 使用情况上报

1. 客户端每日中午12点自动上报
2. 上报内容：版本、操作系统、IP、地理位置
3. 上报失败会保存在本地，待下次重试

## 注意事项

1. 服务器地址在代码中硬编码（`src-tauri/src/constants.rs`）
2. 客户端不展示机器码给用户
3. 激活失败时不返回详细错误信息，防止泄露服务器配置
4. 网络异常时提示"网络异常"，其他错误提示"授权码无效"
